# pcb442 完全图固定点端到端

## 1. 结论

`pcb442` 已完成一次从 97,461 条完全图边开始的单 GPU 端到端消元。正式调试运行使用：

```text
CUDA JV 固定点 -> KH -q（仅 HS）-> CUDA JV 固定点 -> 重复至两阶段均零删除
```

在 10 轮后收敛到 4,015 条边，删除 93,446 条，删除率为 95.880403%。官方最优 tour 成本为 50,778，最终缺边数为 0。第一轮已经降到 12,959 条边，略强于同实例作者 `KH -Jq` 对照的 12,970 条边。

这解决了此前只删 18 条边/只扫描少量 target 的范围错误：`--max-targets` 结果仍是安全的局部实验，但不能再被报告为完整 Local Elimination。

## 3. 实现

### 3.1 完全图与完整扫描语义

- `GraphSnapshot::LoadComplete` 从 EUC_2D/CEIL_2D TSPLIB 坐标直接生成规范 `(u,v)` 排序完全图，并复用已有精确整数距离实现。
- CLI `complete-graph` 写 Concorde/KH 可读的加权边文件。
- `local-eliminate --complete-sweep 1 --target-batch-size N` 将 `N` 解释为内存 tile，而不是全局 target 截断。
- 完整扫描若未收敛、初始/最终边数门禁失败、最优 tour 丢失或从初始快照重放 proof 不一致，会在写输出前失败关闭。
- `--profile kh-jq` 锁定 quick endpoint 候选、10 个 potential points、兼容性过滤前 10 个 `(c,d)` trials、无 point/end 递归等算法参数，防止同名 profile 被静默覆盖。

### 3.2 单 GPU 与作者精确 HS 的分工

- CUDA 负责每轮 JV 候选生成；所有 JV 删除仍由 CPU 逐条精确验证并写现有 proof。
- KH 工具只运行 `-q` 的 HS 部分，避免在 GPU 已到 JV 固定点后重复执行作者 CPU JV。
- 每个 KH-HS 输出随后再次运行 CUDA JV 到固定点；当一整轮 KH-HS 和 JV 都没有删除时才声明收敛。
- `CMakeLists.txt` 直接从只读子模块构建隔离的 `cudaee_kh_elim`/`cudaee_kh_elim_omp`。作者 Release Makefile 不定义 `NDEBUG`，两个目标显式使用 `-UNDEBUG` 保持原行为。
- `tools/run_complete_kh_jq_e2e.sh` 完成输入哈希、空闲 GPU、构建、逐轮执行、JV proof 重放、tour 检查、固定点和强度门禁，并输出 V2 manifest。

KH-HS 仍是作者原始精确算法，而不是浮点/GPU 删除授权。需要明确的是，实验版 KH 不导出 `src/verify.c` 可读取的 Hamilton–Tutte tree；因此 manifest 能重算并审计流水线，但不是逐条 KH 删除的可移植 proof。发布级“独立 verifier”仍需给 KH 增加 witness trace，或将专用 HS 规则迁移到本项目证书格式。当前结果的授权级别应写成 `author-KH-exact-HS-algorithm`，不能写成 `portable-proof-verified`。

## 5. 与作者同强度比较

此前锁定的作者对照为：完全图 97,461 -> 12,970，16 个 CPU 线程，wall 101.14 秒。当前首轮为：97,461 -> 12,959，`0.38 + 96.20 + 0.24 = 96.82` 秒。两者删边强度相当，当前分解的观测加速为 `101.14 / 96.82 = 1.045x`。

这个约 4.5% 的单次结果尚未达到方案中 `>=1.25x` 的默认启用门槛，也没有完成 7 对配对实验，因此只能称为 pilot。单独的 JV 固定点在同一输入上为 CPU 15.64 秒、CUDA 0.40 秒，约 39.1x；但端到端绝大部分时间仍在 CPU HS，所以局部高倍加速只转化为较小的总体收益。

固定点结果 4,015 条边比作者单轮强得多，不能把其约 102 秒与作者 12,970 条边直接当作等强度 speedup。它回答的是“完整删完后有多少边”，不是公平加速比。

## 6. 原生 V3 HT profile 的否定证据

在 CUDA JV 后的 95,994 条边上，`--profile kh-jq` 的 transposed 探针扫描 256 个最大权重 target，用时约 0.52 秒，但 256 个全部 unresolved、HT 删除为 0。原因不是 target 截断，而是本项目通用 HT/k-opt 叶与作者专用 `can_HS_eliminate` 仍不等价。

因此当前端到端脚本使用作者 HS 达到论文强度；原生 V3 transposed/LeafBroker 保留为候选器研究线，不得据此宣称已替代作者 HS。
