# V3 论文对齐与基准协议

## 比较层级

- **Scope L**：只计 Local Elimination，是本分支的主要指标。
- **Scope P**：预处理加 Local，但不包含 LKH 主搜索。
- **Scope R**：从候选图到最终求解的完整流程。

本分支不把 Scope L 的速度直接表述为端到端速度。按 V3 的时间占比估计，Local 加速 `1.25–2.0x` 对 Scope R 只对应约 `1.02–1.06x`；后续必须加速 LP/LKH 才能显著扩大整体收益。

## 运行约束

1. 每轮通过登录 shell 执行 `gpu-free`，选择一张空闲 GPU，并记录主机、GPU UUID、驱动、CUDA、CPU、NUMA 和提交号。
2. 同一组 A/B 在同一主机、同一 GPU UUID、相同环境变量和输入哈希下交替执行。
3. 预热一次后至少运行七组，报告中位数、P25/P75 和全部原始样本。
4. 同时报告 wall、target execution、搜索、建图、leaf、reply、propagation、验证和 commit 时间。
5. 若两个后端的证明强度不同，另外运行相同 transposed 工作与 CPU/GPU leaf 后端的硬件差分，禁止把算法剪枝收益冒充 GPU kernel 加速。

## d15112 32 目标门禁

- 输入、目标 edge id、预算、目标顺序和受保护最优 tour 必须一致。
- 正确性目标：不少于 DFS 基线的 18 个 PROVEN，输出 proof 全部离线验证。
- 性能目标：wall 不高于 `1.286 s`，即相对当前 `1.608 s` CPU 至少 `1.25x`，同时相对当前 `2.845 s` A5000 CUDA 至少 `2x`。
- 未达到 `1.25x` 时保持 opt-in；低于 `1.10x` 时不继续扩大持久化调度器。

## 论文 Table 7 对齐

使用 d15112 的同一输入边哈希，并匹配以下协议：完整 JV、每条活动边最多十组 c,d、全部 Hamilton replies、最多两次 Tutte move。参考 `kh-elim -Jq` 与 `kh-elim_omp -Jq` 在同一现代主机上重新运行，同时保留论文的历史 `39.6 s` 单核和 `1.9 s` 44 核数据。

只有当剩余边达到论文约 `73,840–73,851` 的强度时才给出直接速度比；否则报告“耗时—剩余边数”Pareto 曲线以及达到该边数所需时间。当前 32 目标 pilot 不属于论文同协议比较。
